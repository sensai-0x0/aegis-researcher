### Verified API drift (the pivotal triage decision)

`main`'s core is a **stdlib dataclass API**: `core/scope.py` exposes
`ScopeResolver` + `Decision` (exclusions evaluated before authorizations —
matches this branch's original TDD intent), `core/policy.py` exposes
`PolicyEngine`/`PolicyDecision`/`ActionClass`, `core/audit.py` exposes
`AuditLog`. It has **no pydantic layer**: no `ScopeManifest`/`ToolRequest`
record models, no `Mission.model_validate`, no injected clock, no
`AuditLog.entries()`. Hence all pydantic-model specs
(`unit/test_contract_roundtrip.py`, `unit/test_mission.py`,
`unit/test_scope.py`, `unit/test_policy.py`, `unit/test_evidence_store.py`,
`unit/test_run_manifest.py` — 111 tests) fail against main even though the
behavioral semantics largely agree.

Three reconciliation options, in increasing effort:

- **A. Adapt specs to main's dataclass API** — delete/weaken the pydantic
  model specs. Cheapest, but abandons P02.W3 ("versioned Pydantic models and
  JSON Schema contracts") and the conftest payload-builder canon.
- **B. Port main's core to the pydantic/contract API** (conftest canon).
  Highest fidelity to curriculum; ~6 small modules to rework; all 297 specs
  become the single acceptance net.
- **C. Layer pydantic record models onto main's core as validation
  adapters**; keep dataclass engines, add `model_validate` boundaries and
  clock injection at constructor level. Middle path; specs mostly unchanged.

Recommendation: **B**, decided by the human/loop — the conftest payload
builders are already the canonical test fixtures on this branch, and the
curriculum explicitly requires pydantic contracts.
